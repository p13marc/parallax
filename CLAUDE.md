# CLAUDE.md

This file provides guidance to Claude Code when working with code in this repository.

## Project Overview

**Parallax** is a Rust-native streaming pipeline engine (a GStreamer alternative) built on zero-copy shared memory, hybrid async+realtime scheduling, and progressive typing. Linux-only. Workspace: the root crate (package **`parallax-pipeline`** on crates.io, `[lib] name = "parallax"` — the bare crates.io name is squatted, so package and lib names intentionally differ; imports stay `use parallax::`), `parallax-macros/` (package `parallax-pipeline-macros`, lib `parallax_macros`), `examples/example-plugin` (cdylib plugin demo, publish = false).

- Edition **2024**, MSRV **1.97** (`Cargo.toml` `rust-version`, enforced by the CI `msrv` job; do not claim 1.75/1.85/1.95 — all stale).
- Default features are empty; most media functionality is feature-gated.

### Core Principles

1. **Shared memory first**: all CPU buffers are memfd-backed (always IPC-ready, one fd per arena)
2. **Cross-process refcounting**: refcounts live *inside* shared memory (atomics), release via lock-free MPSC queue
3. **Progressive typing**: dynamic pipelines (string/programmatic) + typed pipelines (compile-time checked)
4. **Sync processing, async orchestration**: element hot paths are sync; orchestration is Tokio; RT-safe elements can run on dedicated RT threads
5. **Pure Rust codecs where possible**; C libraries only when unavoidable

### Key Design Decisions

Dependencies are in `Cargo.toml`; these two are the ones the code alone would mislead you about:

| Aspect | Choice |
|--------|--------|
| Plugin ABI | **Hand-rolled `#[repr(C)]` descriptor + `extern "C"` fns, loaded via libloading.** NOT stabby (old docs claiming stabby are wrong; stabby appears in Cargo.lock only as a transitive dep of zenoh). |
| GPU | Vulkan Video via ash — **experimental scaffold** (see Gotchas) |

## Build & Test Commands

Recipes live in `justfile` (`just --list`); `just check-sensor` mirrors the CI sensor combo.

Feature-gated code is NOT compiled by default — after touching gated modules (codecs, devices, rtp, vulkan…), check with the relevant features enabled. CI (`.github/workflows/ci.yml`) runs default tests plus the sensor combo; it deliberately does NOT run `--all-features` (dav1d/alsa/pipewire/libcamera need system libs, and vulkan-video carries lint debt tracked in #3).

## Element System

Two coexisting generations:

**Legacy traits** (`element/traits.rs`) — most built-ins use these. `Source`/`Sink`/`Element`/`Transform` plus async variants, `Demuxer` (1-to-N), `Muxer` (N-to-1), `SyncElement` (RT path); author traits reach the runtime through per-trait adapters (`SourceAdapter`, `SinkAdapter`, …) that erase into `DynAsyncElement`. Two things the signatures won't tell you:
- Muxer/demuxer nodes are the only ones whose executor task keeps channels **per pad**; every other type flattens them. **Demuxer routing is real since #76**: the executor drives demuxer nodes through `AsyncElementDyn::process_demux` (ABI 3), delivering each `RoutedOutput` entry only to links attached under `Demuxer::pad_name(pad)` — an unlinked pad drops with a rate-limited warn ("" broadcasts, legacy). A demuxer that owns its reader (`Demuxer::produce`) needs no input link and runs as the pipeline's source; `pipeline.add_demuxer(name, d)` registers its pads. Wrappers: `TsDemuxElement` (1-in, pads `video`/`audio`/`data`) and `Mp4DemuxSource` (source-style, DTS-interleaved, pads `video`/`audio`).
- `take_inputs`/`take_outputs` *drain* the per-pad map, so a task spawner must take one form or the other, never both.

**Unified simple traits** (`element/pipeline_element.rs`) — no adapter boilerplate. Wrap a `SimpleSource`/`SimpleSink`/`SimpleTransform` in `Src(...)`, `Snk(...)`, `Xfm(...)` and pass to `pipeline.add_element(name, ...)`.

**ProduceResult** (pool-aware sources): `Produced(usize)` (wrote into ctx buffer), `Eos`, `OwnBuffer(Buffer)` (own memory — CPU-arena or dmabuf-backed alike, #145), `WouldBlock`.

**ExecutionHints** — declare via the profiles (`ExecutionHints::rt_safe()`, `io_bound()`, `cpu_intensive()`, `low_latency()`, …). There is **no `Affinity` type/`affinity()` method** — scheduling derives purely from hints.

**Flush**: executor calls `flush()` repeatedly at EOS until it returns `None`/`Output::None` — implement it in encoders/muxers to drain buffered data.

**Runtime control** (`src/control.rs`, always compiled): `Executor::start()` *moves* elements into their tasks, so `get_element_mut()` returns `None` on a running pipeline. The only way to mutate a live element is an `Arc<Atomic*>` **handle cloned before `start()`**. Every controllable element implements `Controllable`, so the accessor is always `control()`: `EncoderControl` (bitrate/GOP/QP/rate-control/skip-frames/keyframe), `EncoderStatsHandle` (read-only counters), `KeyframeHandle`, `ScaleControl`, `ThrottleControl`, `JpegQualityControl`, `ValveControl`, `GainControl` (volume, linear or dB), `FlowStateHandle`, `AutoVideoSinkHandle` (#74: window events — `VideoWindowEvent`/`VideoKey` over a bounded lossy channel, `try_event`/`event_timeout` — plus `set_fullscreen(bool)`; taken via `sink.handle()` *before* start, no handle = no events). See `docs/elements.md` § Runtime control.

**Geometry-in-Metadata invariant**: geometry travels in-band. **No element takes dimensions at construction** — `H264EncoderConfig::new()`, `JpegEncoder::new()`, `PngEncoder::new()`, `VideoScale::new()`, `EncoderElement::new(enc)`, `HwEncoderElement::new(enc)`, `Rav1eConfig::default()` and `V4l2M2mEncoderConfig::new()` are all dimension-free. An element that cannot determine its geometry from `Metadata` **errors**; it never falls back to a stale constructor value. Lazily-built state (an output arena, a rav1e context, the V4L2 M2M driver queues) is created on the first frame and rebuilt on a resize.

## Pipeline

### Construction

- Either `Pipeline::parse("…")` (see grammar limits below) or the programmatic `add_source`/`add_transform`/`add_sink`/`add_element` + `link`. `add_filter` takes `Element` impls; `add_source_with_arena`/`_with_pool` supply the source's memory.
- `p.link(a, b)` is shorthand for `p.link_pads(a, "src", b, "sink")`.
- `get_element::<T>(name)` / `get_element_mut::<T>(name)` downcast by node name; `name=` in parse strings sets the name, otherwise `{factory}_{index}`.
- Fluent alternative: `PipelineBuilder` (typestate; `source().then().tee(..).sink().build()`), see `pipeline/builder.rs`.
- `add_node` is `pub(crate)` — never show it in docs/examples.

### Parse grammar (IMPORTANT limitations)

- Strictly **linear chains**: `elem prop=val ! elem ...`. NO caps filters, NO tee branching (`t. !`), NO bins. Fan-out requires the programmatic API.
- Property values: quoted strings, bare words, ints, floats, bools (`true/false/yes/no`).
- **The factory registers most of the element library** (#187): ~37 always-on names (io/testing/util/flow/transform/timing/network/ipc/streaming) plus ~30 feature-gated ones (codecs, devices, rtp) — `src/pipeline/factory/` is split per domain, `docs/elements.md` § "Pipeline-string factory names" is the reference table. Constructors get a `Props` view (`factory/props.rs`); **an unknown property is a hard error** (consumption-tracked, `finish()` rejects leftovers — `name` is pre-consumed), and a name whose feature is off errors "requires cargo feature \"X\"" via the unconditional `GATED_ELEMENTS` table, not "unknown element". `ElementConstructor` is `fn(&Props) -> Result<Box<DynAsyncElement>>` (non-capturing closures coerce). Still unregistered: mux/demux (parser can't express pads), zenoh (async constructors), rtsp, closure/handle elements (Map/Filter/AppSrc/AppSink), v4l2-m2m/vulkan. Parse/factory errors are `Error::Parse` (bare message), not `InvalidSegment`.
- **`parallax-launch` binary** (feature `cli`, `src/bin/parallax_launch.rs`): gst-launch equivalent — `parallax-launch videotestsrc num-buffers=100 ! videoconvert ! nullsink`. `-v` all bus messages / default warnings+errors / `-q` errors only; `--list-elements` (registered + unavailable-gated); `--dot` prints the graph and exits. Exit codes 0 EOS, 1 error, 2 usage, 130 interrupted (first ^C graceful `stop()`, second hard-exits). Network/device constructors do real I/O at parse time (like the programmatic API). Tests: `tests/launch_cli.rs` (`cargo test --features cli`).

### States (PipeWire-inspired)

`Suspended <-> Idle <-> Running`, plus `Error` (recover via Suspended).
`prepare()` (validate+negotiate+allocate; converter policy applies), `activate()`, `pause()`, `suspend()`. `run()`/`start()` auto-prepare from Suspended.

### Execution

- `pipeline.run().await` — run to completion. `pipeline.run_with_bus(|msg| bool).await` — the handler runs *while* the pipeline runs, and returning `false` really stops it (cooperative stop → EOS).
- `Executor::with_config(cfg)`; **`executor.start(&mut p)` is SYNC** and returns `PipelineHandle`; `handle.wait().await`. Only `executor.run()` is async. Never write `executor.start(...).await`.
- `ExecutorConfig` presets: `low_latency_audio()`, `video(fps)`, `hybrid()`. `auto_strategy` defaults to true.
- **`ElementStrategy` has exactly two variants: `Async` and `RealTime`.** Auto rule: `rt_safe && latency ∈ {UltraLow, Low}` → RealTime; else Async. `trust_level`/`uses_native_code` are currently IGNORED (process isolation was removed in commit da6df59 — never document an "isolated process" strategy).
- Hybrid mode: `RtScheduler::partition_graph` splits nodes, boundary edges get `AsyncRtBridge` (lock-free SPSC + eventfd), RT threads use PipeWire-style `ActivationRecord`s, paced by `TimerDriver`/`ManualDriver`.
- `SchedulingMode::RealTime` with zero RT-safe nodes falls back to fully-async and logs a `warn!` (it does not error). `ExecutorConfig::scheduling` is authoritative — the executor overrides `RtConfig::mode` from it, so `with_scheduling(RealTime)` works on its own. `auto_strategy` only *reports* that RT-safe elements exist; it does not promote an Async config to Hybrid.

### Bus & events

- `Bus`/`BusHandle` carry `MessageKind` variants. Consume with `poll()`, `next().await`, `subscribe()` (broadcast), `wait_for_eos_or_error().await`, or `into_stream()` — a `futures::Stream`, so it composes with `select!`.
- Separate typed event channel: `PipelineHandle::subscribe() -> EventReceiver` (`pipeline/events.rs`) — distinct from the bus.
- **Terminal outcome**: `PipelineHandle::ended() -> Ended` (a `Future<Output = EndReason>`) / `end_reason()`. Backed by a `watch`, so it **retains** the answer — a late observer still gets it. `EndReason::{Eos, Error(StreamError), Aborted}` lives in `pipeline::events` (re-exported from `elements`); `stop()` ends as `Eos`, `abort()` as `Aborted`. Prefer it to `EventReceiver::wait_eos()`, which is broadcast-backed and loses a terminal event sent before you subscribed. `PipelineHandle::stopper() -> Stopper` outlives the handle, which `wait()` consumes.
- In-band events live in `src/event/` (downstream, upstream, and bidirectional families). `PipelineItem::{Buffer, Event}` keeps buffers and events ordered through channels.

### Seeking / probes / tracers / typefind / flow control

- Seek (#162, GStreamer-parity audit): an element opts in through its trait's optional methods — `is_seekable`, `handle_upstream_event` for `Event::Seek`, `query_position`/`query_duration` exist on `Source`, `Demuxer` AND `SimpleSource` (all forwarded by their adapters). **Seeks are gated**: with no source declaring `is_seekable()` (snapshotted at start into `SourceControl`), `PipelineHandle::seek*` returns `false` immediately — nothing dispatched, flushed or posted (`send_event_upstream` is the ungated escape hatch). **Dispatch is hop-by-hop** (#163 phase A): in fully-async pipelines the event enters at the sink inboxes and travels toward the sources — every element's `handle_upstream_event` gets its chance (all adapters forward it; `Sink`/`AsyncSink`/`Muxer` now carry the defaulted method too), `NotHandled` forwards to every parent, a mid-graph `Handled` runs the flush trio from *that* task and posts SeekDone naming it, and per-task dedup collapses diamond delivery, ordered by `SeekEvent::epoch()` — seqnum and refinement round folded into one monotonic ordinal (#173) — so a duplicate is dropped but a same-seqnum refinement round passes. Hybrid pipelines keep the legacy direct fan-out (RT segments carry no events). **Every channel here is `tokio::sync::mpsc`** — the per-edge data links and the upstream inboxes alike. `Receiver::recv` is documented cancel-safe ("it is guaranteed that no messages were received"), so the three select-carrying loops (sink, transform, fed demuxer) `select!` directly over `&mut rx`: no stashed-future apparatus, no per-buffer boxing. kanal was removed because its async recv is cancel-unsafe *in a way that loses data*: with a sender already committed to the handoff, `ReceiveFuture::Drop` completes it and **discards the message** while the sender's `send` returned `Ok` — a swallowed `Message::Eos` hangs a consumer forever. (An earlier note here blamed a lost waker: wrong mechanism, right conclusion.) The rule that survives is the mirror image — **never put `Sender::send().await` in a `select!` branch**: tokio guarantees the message was not sent, but it *is* dropped. No send in the executor sits inside a select; keep it that way. Runtime queries: `PipelineHandle::{seekable, query_seekable, duration, query_duration}`; the pre-start `Pipeline::query_*` shares the same `aggregate_seekable` fold. `SeekEvent` carries a **private auto-assigned seqnum** (constructors only — `new_time`/`new_bytes`/`new(format, start)`; no struct literals); a flushing seek raises **the handling node's own** flush-epoch cell to `SeekEvent::epoch()` (seqnum×16 + refinement round) via `fetch_max` (idempotent across N handling sources; per-node since #163 phase C — the shed's scope equals the flush trio's scope, so a seek on one chain never drops an innocent sibling chain's in-flight buffers, and fan-in into a non-muxer is now a link-time error, #183), and `MessageKind::SeekDone{seqnum, source, format, position}` correlates completions. `EventResult::Handled{position}` reports the actual landing (FileSrc: resulting offset, also for Current/End; MP4: snapped keyframe; MKV: the cue time on a backward snap, honest `None` on a forward one), which feeds the synthesized `Segment` and `SeekDone`. Non-flushing seeks are *queued seeks*: the Segment rides FIFO behind queued data, nothing is dropped. `KEY_UNIT` is effectively always-on for container demuxers; **`SNAP_BEFORE`/`SNAP_AFTER` are honored** (#166): unset = per-container default (MP4 backward, MKV forward), both bits = nearest (`SeekFlags::snap() -> Option<SeekSnap>`, MKV resolves at cue granularity and degrades to forward on cue-less files; `Mp4Demux::seek_to_time`/`seek_all_to_time` take a `SeekSnap`, secondary tracks always land at-or-before the reference). **`ACCURATE` drives iterative refinement for push-mode demuxers** (#173): `TsDemuxElement` keeps an ACCURATE seek in flight after translating it — each flush arms it to judge the first post-flush PTS, a miss beyond 500 ms stages a `derive_refined` BYTES seek (same seqnum, next round; the executor polls `Demuxer::take_upstream_event` after every `demux` — the only way a fed element originates upstream traffic) re-estimated from the anchors the mis-landing itself contributed, bounded at 3 rounds, with SeekDone held until refinement stops. **ACCURATE is honored end to end** (#165): the synthesized segment starts at the *requested* time — ACCURATE outranks the always-on KEY_UNIT, else it would be unreachable — while data starts at the snapped keyframe; the gap is out-of-segment on purpose, so decoders decode-but-drop it (h264/dav1d/vpx via `SegmentClip` in `codec/common.rs`; flush drains loop past clipped frames so a clipped tail can't end the EOS drain) and a sync `AutoVideoSink` drops below-start PTS instead of blitting them unpaced. SeekDone still reports the honest landing (audio sample-trim remains open). `Queue2` drops its buffered ring on `FlushStart` (file-backed state survives deliberately) and is **buffering-aware in download mode** (#164): buffers' `Metadata.offset` — stamped by FileSrc/HttpSrc — keeps `DownloadedRanges` in true stream offsets across seeks (sparse download file at real offsets, honest holes; percent counts downloaded bytes, not the write cursor), a forward BYTES/Set seek within `BufferingConfig::seek_forward_threshold` (default 512 KiB) of the write position is **absorbed** — `Handled`, flush trio from the queue's own task, `skip_until` discards-but-records arriving data to the target (a straddler is `slice()`d; a FlushStart from upstream cancels the skip, a newer seek supersedes it) — everything else (backward, far, relative, TIME, unstamped input) is NotHandled and reaches the source, whose post-seek byte Segment re-anchors the queue (its `stop` also teaches it the total). Progress: `Queue2RangesHandle` via `control()` (cloned before start) + throttled `MessageKind::DownloadProgress`. True serve-from-disk (backward seeks into downloaded spans) is NOT possible mid-pipeline — a transform cannot emit without input; that half is **`HttpCacheSrc`** (#188, feature `http`, factory `httpcachesrc`): `HttpSrc`'s ranged download fused with the sparse-cache bookkeeping into one seekable SOURCE — write-through cache at true stream offsets (unlinked temp file, or `with_cache_file`), a seek into a downloaded span moves only the read cursor (served from disk, works even on range-less servers), anything else reconnects lazily at the target; shares `Queue2RangesHandle`/`RangesShared` (now `pub(crate)`) and `DownloadedRanges::contiguous_run_end` is the serve-from-disk query. `HttpConnection`+`HttpSrc::connect` are `pub(crate)` for it, and the hand-rolled HTTP test server lives in `http.rs`'s `pub(crate) mod testserver` (request-counted — the serve-from-disk proof). The enabling fix: `ElementAdapter`/`BoxedElementAdapter`/`TransformAdapter`/`AsyncTransformAdapter` now forward `handle_downstream_event` (it was silently swallowed by the dyn default — any `Element`-authored event handling was dead code in running pipelines). **`INSTANT_RATE_CHANGE`** (bit 1<<9, #165) is **sink-terminated**: `PipelineHandle::set_rate(rate)` / `SeekEvent::new_instant_rate` offer the seek to each sink and stop there — no flush, no Segment, no upstream travel (a demuxer must not reposition), one SeekDone (position None) per applying sink — and the seekability gate is lifted for this flag, so a live pipeline can change rate. `AutoVideoSink` applies same-sign rates to its own mapping and re-anchors its pacer; sign flips decline (reverse needs a real seek); a later real seek's Segment re-establishes its own rate. There is deliberately NO downstream InstantRateChange event: parallax has no out-of-band downstream path, so it would arrive a queue-depth late. Audio is out of scope (AlsaSink paces at hardware rate). Seekable built-ins: `FileSrc` (`SegmentFormat::Bytes` only), `HttpSrc` (Bytes via `Range`; server capability probed by the `is_seekable` snapshot at start — the probe IS the first GET, bounded by `with_timeout`), `AppSrc` (by proxy), `Mp4DemuxSource`, `MkvDemux` (Time). Types that no longer exist: `SeekableSource`, `SeekRequest`, `Event::LatencyQuery`. (`Event::Qos` EXISTS again since #184 — see the QoS bullet below.)
- **Seek translation** (#163 phase B): a mid-graph element answers an upstream event with `EventResult::Forward(Box<Event>)` to send a *different* one on in its place — the fourth answer next to Handled/NotHandled/Error, and how a **fed** demuxer turns a TIME seek into a BYTES seek on its source. Build the replacement with `SeekEvent::derive(format, start)`: the seqnum is private, so `derive` can only copy an existing one, never mint — and the executor *validates* that (a replacement with a different seqnum is dropped with a bus warning, because a renamed seek would break `fetch_max` idempotence and SeekDone correlation). The `Forward` arm bumps no epoch and runs no flush trio: the source that handles the derived seek does all of that. `EventResult` therefore lost `Copy`/`PartialEq` — compare with `matches!`. **ABI 4→5** (the return layout changed, plus `seek_translations`/`flush_demux` vtable slots). `Demuxer` gained `handle_downstream_event` (the source's post-seek `Segment` — byte segments now carry the stream total as `stop`, the only way a translator learns the file size) and `flush() -> RoutedOutput` (driven by `AsyncElementDyn::flush_demux`, which keeps pad routing where the flat `flush` would broadcast a video AU down the audio branch; `DemuxerAdapter` also clears its `pending`). Called on FlushStart with output discarded, at EOS with it routed — the only chance a fed demuxer gets to emit its tail, since its `produce` is never called. `seek_translations()` (declared by *any* node, snapshotted at start from all of them) makes `SeekableQuery::format` report `Time` instead of the source's `Bytes` — GStreamer's rule that a demuxer refuses byte seekability downstream. The range does not survive the swap; `seek_bytes()` still reaches FileSrc honestly. `TsDemux` places the seek with `TsByteIndex` (PCR-derived sparse anchors, 100 ms apart, ≤8192, linear interpolation; `reset_parser()` = `reset()` minus stats and index, which is what a flush needs). Under two anchors it **refuses** rather than guessing. Gotchas that cost real debugging: a TS fixture needs `psi_interval != 0` (default 0 = head-only PSI, and a parser reset never recovers), and a file small enough to fit in the pipeline's channel buffers is read to EOS before a seek can reach the source — the seek then has nothing to act on.
- **Runtime pause/resume/position** (#71): `PipelineHandle::pause()/resume()/is_paused()/position()`. Pause freezes a `clock::PausableClock` that `Executor::start` wraps around the selected clock *before* distributing it (elements hold a copied base_time, so the shared wrapper is the only post-start lever) and gates via a `watch`: **producer loops** (sources AND source-style demuxers — #156; control events still drain so a seek can land while paused) and **sink loops** — a gated sink delivers `Event::Pause`/`Event::Resume` to its element once per transition, drops stale-epoch buffers while holding, stashes the first fresh buffer for replay on resume (pause ≠ flush), and lets Eos/Error end the run. Transforms/fed demuxers are deliberately ungated (flush must propagate while paused; backpressure parks them). Resume is gap-free (the paused span folds into the wrapper's offset). Posts `StateChanged{Running↔Idle}`. `position()` = max last-presented PTS across sinks (reset on FlushStop, re-anchored by a seek's `Segment`), falling back to running time before the first present. `AutoVideoSink`'s pacer polls the clock in ≤10 ms slices (a one-shot sleep would keep presenting against a frozen clock) and re-anchors on FlushStop. **AlsaSink pauses crisply**: on `Event::Pause` it freezes its `AlsaPosition` (the master clock genuinely stops, so the fold matches reality) and `snd_pcm_pause`s where hardware supports it, else drops the ≤85 ms device buffer counted-as-played; resume unfreezes symmetric. Caveat: an element blocked *inside* `process`/`consume` sees the gate when the call returns; RT nodes see no gate. Blocking element code (thread::sleep in a sync consume) can stall the tokio time driver — test polling against such elements must use `yield_now`, not timers.
- **Segment discipline** (#165 slice 1): every buffer is preceded by a Segment. Each producing task emits `StreamStart` at startup and a **lazy initial Segment** anchored at its first buffer's PTS — or Bytes-from-0 when the source's `query_duration` answers in Bytes (FileSrc/HttpSrc; `Metadata::default().pts` is ZERO not NONE, so PTS can't distinguish untimestamped). Demuxers/muxers **own their pads' stream identity**: per-pad StreamStart + per-pad lazy Segments (each pad anchors at its own first PTS), upstream StreamStart/Segment swallowed *after* being offered to `handle_downstream_event` (the #163-phase-B rewrite hook) and *before* src-pad probes; pads re-anchor on a forwarded FlushStop. The post-seek Segment carries `seek.rate`/`seek.stop`; **`base` accumulates on non-flushing seeks** (#165: each producing task's `SegmentTracker` records running time consumed under the outgoing segment — flushing seeks restart at base 0; either demuxer branch keeps ONE tracker across pads, ~a frame of A/V base skew). **Fed demuxers own their post-seek pad segments too** (#165): `PendingTranslation` carries the original seek's rate/flushing/stop, and the source's in-band Segment — which rides FIFO at exactly the old/new data boundary — triggers the pad re-anchor (`PadReanchor`) with that shape: rate survives the translation (it used to be dropped), a non-flushing translated seek re-anchors at all (it used to never re-anchor — no FlushStop ever comes back), and its base is accumulated through the queued drain. **SEGMENT seeks** (`SeekFlags::SEGMENT`, bit 1<<3): the demuxers honor `seek.stop` (playback really ends there — also for plain seeks with a stop), and at range end the producing task posts `MessageKind::SegmentDone` *instead of* EOS, then idles awaiting the app's follow-up non-flushing SEGMENT seek — gapless looping, GStreamer's model (`with_loop` remains the zero-config silent-rewind convenience). applied_rate stays 1.0. A pre-first-buffer seek suppresses the lazy initial segment (`handle_upstream_hop` returns a `HopOutcome`). `AutoVideoSink` stores the current Time segment and paces in segment running time (`to_running_time`; PTS past the stop present immediately, PTS below the start are dropped in sync mode — #165 ACCURATE clipping); the first-frame anchor survives as the latency absorber. Sink `position()` re-anchors from the initial segment, so a stream starting at t>0 reports honestly from its first buffer.
- **QoS events** (#184): `Event::Qos(QosEvent{qos_type: Underflow|Overflow, proportion, jitter_ns, timestamp, processed, dropped})` is the second upstream event family. **Sinks originate**: `Sink`/`AsyncSink` gained defaulted `take_upstream_event()` (mirroring `Demuxer`'s; NO ABI bump — the dyn slot predates it), polled by the sink task after each consume; the event rides the #163 hop-by-hop transport toward the sources and is mirrored onto the bus (`MessageKind::Qos`, redesigned to match the event; `post_qos(&QosEvent)` finally has a caller). **Consumers observe-and-forward** (return `NotHandled` so it keeps travelling; key decisions on `proportion` — it's idempotent, the counters can double-count in diamonds): `Throttle` scales its interval by the proportion (reduction-only, 1 fps floor; recovery is app policy via `ThrottleControl`). **No dedup/rate-limit in the transport** — origins MUST throttle emission (≲1/s), the inboxes are unbounded. **Latency** (#184): elements that hold data by design declare `latency() -> Option<LatencyRange>` (defaulted on `Element`/`Sink`/`AsyncSink` + the dyn trait — THE ABI-8 bump; declarers: RtpJitterBuffer fixed(latency_ms), AutoVideoSink up_to(max_lateness) when sync). `Pipeline::query_latency()` sums along every source→sink path (worst path wins), `Executor::start` snapshots it into `PipelineHandle::latency()` and posts `MessageKind::LatencyChanged{min,max}` exactly once when any element declared — the variant is finally honest. Static aggregate only, no event round-trip; AutoVideoSink keeps its first-frame anchor.
- **Runtime seek & in-band events** (#72): on a *running* pipeline use `PipelineHandle::seek/seek_time/seek_bytes/send_event_upstream` — the graph-level `Pipeline::seek*` is dead after `start()`. The executor's channels carry `Message::Event` alongside buffers (FIFO-ordered with them); a handled flushing seek bumps **the handling node's own flush-epoch cell** (per-node since #163 phase C; each `InputBranch` carries its producer's cell), then broadcasts FlushStart → FlushStop → Segment from that task and posts `MessageKind::SeekDone`. Every `Message::Buffer` is stamped with its producer's epoch; a consumer judges staleness against the cell of the branch the buffer arrived on and **folds the observed epoch into its own cell** (`InputBranch::is_stale`), so the shed propagates hop-by-hop at receive speed strictly along the seek's path — the queued pre-seek backlog drains in microseconds while sibling chains are untouched (transforms/muxers stamp outputs `max(input's epoch, own cell)` — the own component is what keeps a mid-graph handler like Queue2 coherent, since its upstream never bumps; a mid-graph handler's *input-side* backlog is deliberately no longer shed — Queue2's `skip_until` wants that data). Muxers check staleness per input branch. On FlushStart transforms/demuxers get `flush()` called with the output *discarded* (sinks do not — a sink's flush commits, e.g. finalizes an MP4; `AlsaSink` reacts to FlushStart by dropping its device buffer and rebasing `written_frames` so the master clock continues from what was actually heard). Event probes (`EVENT_DOWN`/`EVENT_FLUSH`) fire on both the emitting src pad and the receiving sink pad. Async strategy only; RT-scheduled nodes see no events. Muxers count FlushStart/Stop across inputs like EOS.
- Probes: `pipeline.add_probe(PadRef::src(node), ProbeType::BUFFER, |data| ProbeReturn::Ok)`. A probe returning `Remove` unregisters itself; `Drop` sheds the buffer.
- Tracers: `TracerRegistry` + `LatencyTracer`/`FramerateTracer`/`DropTracer`; env `PARALLAX_TRACERS="latency;framerate;drops"`; DOT dumps via `PARALLAX_DOT_DIR`; `pipeline.to_dot()`/`to_json()`; `pipeline.stats_snapshot()`.
- **A panicking probe or tracer callback cannot kill the pipeline** (#92): caught inside `ProbeRegistry::invoke_*`/`TracerRegistry::notify_*`, logged at `error!`, and the offender is *removed*. Both registries also de-poison their mutex, so one panic cannot turn into a second failure in every element task. Element panics are different — those are real failures and still end the run (`Error::Panic`, #85).
- Typefind: `TypeFindRegistry::with_builtins()`, then `detect`/`detect_from_extension`/`detect_with_fallback`.
- Flow control (`pipeline/flow.rs`): **there is no `Queue` element and no `FlowPolicy`/`FlowStats`** — the link channel is the queue (capacity via `link_pads_full`, loss via `LinkPolicy`). `FlowSignal` is `Ready | Busy`, produced by the executor from link-channel occupancy: link methods return `LinkId`, `pipeline.monitor_link(id)` / `monitor_link_with(id, WaterMarks)` return the `FlowStateHandle` (sampled both sides of the channel; RT/bridge edges unmonitored); live sources accept `set_flow_state(handle)` and must check `should_produce()`.
- `Queue2` (elements/flow) is the buffering variant — `stream`/`download`/`timeshift` constructors — and posts `MessageKind::Buffering`.

## Memory Model

- `SharedArena::new(slot_size, slot_count)` — memfd + MAP_SHARED. Layout: `ArenaHeader (64B) | ReleaseQueue (MPSC ring, 1024 entries) | SlotHeader[N] (8B: state+refcount packed in ONE AtomicU64, #177) | SlotData[N]`.
- `arena.acquire() -> Option<SharedSlotRef>` (owner only), `slot.ipc_ref() -> SharedIpcSlotRef` (rkyv-serializable), `unsafe SharedArena::from_fd(fd)` / `SharedArenaCache::map_arena` (client), `arena.reclaim()` drains released slots O(k) — plus a one-shot O(n) sweep when a full ring orphaned a drop (`ArenaHeader.orphaned`; sound because acquire is a single CAS, so `(Allocated, rc=0)` always means "released"). `slot_from_ipc` refuses resurrection from rc==0 (stale ref → `None`); `IpcSink` therefore pins each in-flight buffer with a live `Buffer` clone until the peer's post-mapping ack returns (#179: through the shm ack ring, released by a standing reaper task — reaping only inside `consume` deadlocks a source whose arena ≤ the in-flight window).
- `FixedBufferPool::new(buffer_size, count) -> Result<Arc<Self>>`; `acquire()` blocks on the arena's **release doorbell** (#180: a process-local eventfd rung by every last-ref drop after the queue push; zero-waiter ring is syscall-free; remote drops are covered by a 250 ms safety-net re-check), `try_acquire()`, `PooledBuffer` returns slot on drop. **Sources only** — blocking on an element task parks a Tokio worker. Sources use `ctx.acquire_buffer()` inside `produce()`. `OutputArena::admit_within(timeout)` is the bounded-wait sibling of `admit()` (not wired into any built-in element). `EventFd` lives at `memory::EventFd` (moved from `pipeline::rt_bridge`; blocking `wait_timeout` added, non-Linux fallback deleted).
- **Output arenas are executor-sized** (#84, #91, #189): `OutputBudget` = `max(link capacity + consumer's retained_buffers() per src pad, summed across pads) + IN_FLIGHT_MARGIN` — `retained_buffers()` (ABI 10) is how a consumer that keeps buffers past delivery declares its hold (AutoVideoSink: display queue + presented frame = 4; AppSink: `max_buffers`; snapshotted before any element is taken). **When a budget arrived, it wins outright: the static `memory::defaults` floors apply only to budget-less standalone arenas** (pre-#189 the floor overrode a smaller budget, which both over-allocated ~64×3 MB decoder arenas and masked unaccounted retention). Delivered via the defaulted `set_output_budget` — which is on **every** element trait that can emit: `Element`/`Transform`/`AsyncTransform`/`Source`/`AsyncSource`/`Muxer`/`Demuxer`/`SyncElement`/`PipelineElement`/`Simple*`/`AsyncElementDyn`. `max` not sum per pad — fan-out clones share one slot. **Every output arena in the tree is a `memory::OutputArena`**; a hand-rolled `Option<SharedArena>` is a bug. Its surface: `acquire` (default), `try_acquire` (**sources only** — `Ok(None)` → `ProduceResult::WouldBlock`, because nothing sheds a source's `PoolExhausted`), `admit()` (encoders, before irreversible work), `reset()` (geometry change), `grow_to_fit()` (output size follows the input, no ceiling to enforce). Slots are 64-byte aligned, so `SharedArena::new_avx` is never needed. `memory::defaults` holds the floors and the `MAX_OUTPUT_ARENA_BYTES` clamp.
- **No process-wide static arenas remain** (#95 closed): `demux/mpegts.rs` went per-instance with #76 (`TsDemux` owns an `Arc<Mutex<OutputArena>>` shared with its `FrameCollector`s, budget-fed through `TsDemuxElement`), and `KlvEncoder` owns its own grow-to-fit `OutputArena` — which is why `to_buffer`/`to_st0601_buffer` take `&mut self`. One arena is deliberately *not* `OutputArena` and says so in a comment: `Mp4MuxTransform::flush`'s (one slot, sized to the finished file). (`IpcSink`'s placeholder arena is gone — #179 registers the *upstream* buffers' real arenas on first sight, which the placeholder never could.)
- `Buffer<T=()>` = `MemoryHandle` (slot+offset+len) + `Metadata`; clone = two atomic increments (slot + arena refcount) plus a `Metadata` clone — no payload copy and **no syscall** (the arena fd is shared via `Arc`, not dup'd; `benches/memory_pool.rs` guards this). `slice()` = zero-copy sub-buffer.
- `Metadata`: timestamps plus a typed custom map keyed by `&'static str` on a `"domain/type"` convention (`stanag/*`, `h264/*`, `app/*`, …). Transforms MUST clone/propagate metadata or PTS is lost.
- **Video dimensions in metadata**: ONE representation (#160) — `Metadata.format` (`MediaFormat::VideoRaw`). Write with `Metadata::set_video_dims()`, read with `video_dims()`; the legacy `"width"`/`"height"` `u64` custom keys are retired and carry no geometry (they are ordinary app data now). An element that touches `format` directly instead of `set_video_dims()` loses the framerate a source negotiated.
- **DMA-BUF flows through the pipeline** (#145): `MemoryHandle` is an ENUM — `Cpu{slot,offset,len}` | `DmaBuf{slot: Arc<DmaBufSlot>,offset,len}` (`new`/`with_len` still build Cpu; `from_dmabuf[_with_len]` the other). `DmaBufSlot` = Arc'd `DmaBufSegment` + release hook fired once on last drop (V4L2 re-queues the index; `fd()` is #62's import hook). `as_bytes()` infallible on both (live mapping); `as_mut_slice` Option (None = read-only mapping); `slot()`/`ipc_ref()`/`arena_*` return Option (None on DmaBuf — IpcSink errors gracefully + pins cpu_only caps); `Buffer::copy_to_cpu(&arena)` is the copy bridge (`memorycopy`'s real DmaBuf→Cpu direction; the GPU directions stay stubs). **Gating**: sources get `set_negotiated_memory` (mirrors set_output_budget; ABI 9) from the link's negotiated type — V4l2Src emits dmabuf only for `dmabuf_export && negotiated == DmaBuf` (explicit QBUF/DQBUF, one mmap per buffer at open, release-hook recycling, `buffer_count` = backpressure depth, WouldBlock when downstream holds every slot; **compile-only validated — no camera on the dev box**, PTS from CLOCK_MONOTONIC at dequeue since the v4l crate hides per-buffer meta outside next()). **Caps default changed**: undeclared (`Caps::any`) elements now accept ANY memory (dmabuf is CPU-readable); explicit per-format declarations stay cpu-only and force a `memorycopy`. Test tools: `DmaBufTestSrc` (memfd pool, real producer discipline), udmabuf unit test. Deleted: `DmaBufBuffer`, `ProduceResult::OwnDmaBuf`.
- IPC helpers: `memory::ipc::{send_fds, recv_fds, send_segment_handle, recv_segment_handle}` (SCM_RIGHTS, max 4 fds/message).

## Caps & Negotiation

- Constraint model: `CapsValue<T>::{Fixed, Range, List, Any}`; `VideoFormatCaps`/`AudioFormatCaps` → `FormatCaps`; `MemoryCaps` (`cpu_only()`, `dmabuf_only()`, `dmabuf_preferred()`, `any()`); pair = `FormatMemoryCap`; element declares preference-ordered `ElementMediaCaps` via `output_media_caps()`/`input_media_caps()`.
- Solver (`negotiation/solver.rs`) negotiates **per link, first intersection wins** (NOT a global constraint solver).
- On a mismatch, `diff_caps()` reports which **`ConvertAxes`** (`FORMAT|GEOMETRY|RATE|MEMORY`) conflict, and `ConverterRegistry::plan()` covers them with the cheapest **chain** (several converters per link). It returns `None` — a negotiation error — if it cannot cover them ALL; a partial chain is never emitted. Chain order: downscale ⇒ scale-then-convert, upscale ⇒ convert-then-scale.
- Registered: `videoconvert` (FORMAT), `videoscale` (GEOMETRY), `audioconvert` (FORMAT), `audioresample` (RATE), `memorycopy` (MEMORY), `identity` (NONE — so it can never be auto-inserted). Factories take a `ConversionRequest` and configure themselves from the sink's caps.
- Auto-insertion only fires when the **source** side pins the property (`Any ∩ Fixed = Fixed` never conflicts) — i.e. v4l2/screen-capture-rooted graphs and `EncoderElement`.
- `ConverterPolicy::{Deny (default), Warn, Allow}`; `pipeline.prepare()` fails with a helpful error under Deny; `prepare_with_auto_converters()` = Warn; `set_converter_policy(...)`.
- `MemoryLayout::{NONE, SSE, AVX, AVX512}` requests aligned buffers. Nothing in the tree calls `SharedArena::new_avx`/`new_avx512` any more: plain `new` is already 64-byte aligned, which covers all four.

## Clock System

- `ClockTime` is ns with `ZERO`/`MAX`/`NONE` sentinels; arithmetic saturates and propagates `NONE` rather than panicking.
- `SystemClock` (monotonic) and `PipelineClock` (base_time, `running_time()`, async `wait_until`/`wait_for`) implement the `Clock` trait.
- `ClockProvider::{provide_clock, clock_priority}` — priority bands: 0–99 software, 100–199 hardware audio, 200–299 network, 300+ PTP.
- **Automatic selection**: executor calls `pipeline.select_clock()` before start — highest-priority element-provided clock wins (`AlsaSink` provides one at priority 150, derived from frames the device actually consumed via `snd_pcm_delay`, not from wall time). Manual override: `set_clock`/`use_clock_from`.
- **Every element gets the clock**, not just sources (#65): `set_clock` is applied like `set_bus`, and the accessors are the same on both sides — `ctx.clock()` / `running_time()` / `clock_time()` / `base_time()` on `ProduceContext` in `produce()` and on `ConsumeContext` in `consume()`. Only the sink adapters and source adapters override `set_clock`; the trait default is a no-op.
- A sink that paces presentation must treat `running_time() == ClockTime::NONE` as "consume as fast as buffers arrive" — see `AutoVideoSink`'s `sync` property.

## Gotchas & Pitfalls (read before writing code or docs)

1. **No process isolation.** Removed in da6df59. `ElementStrategy` = Async|RealTime only. Old docs mentioning `run_isolated`, `ElementSandbox`, "isolated process" strategy, or `src/execution/` are describing deleted code.
2. **Two `PixelFormat` enums**: `format::PixelFormat` (15 variants, caps) vs `converters::PixelFormat` (9 variants, actual conversion). Separate types, but conversion is explicit: `From<converters::PixelFormat> for format::PixelFormat` (total) and `TryFrom` back (partial). Same split for `SampleFormat` (`format::` vs `converters::audio::`), with no conversion impls.
3. **`Tee` no longer exists** — it was a 1-in/1-out passthrough counter that never fanned out, and is now `Inspect` (`tee` remains a deprecated parse alias). **Fan-out needs no element**: link one src-pad to several sinks. Each `Link` carries a `LinkPolicy` (`Block` default | `DropNewest` | `DropOldest`, #169) — a `Block` branch that fills its channel back-pressures the source *and every sibling*, so use `pipeline.link_lossy()` (DropNewest) on branches allowed to fall behind, or `link_with(.., LinkPolicy::DropOldest)` where the consumer should always see the freshest buffer (live preview). DropOldest links ride an internal leaky channel (`pipeline/leaky.rs` — tokio mpsc senders can't evict); its `send_lossy`/`send_control` never await, so `OutputBranch::send_buffer` charges tokio's coop budget (`consume_budget`) on the lossy paths — without it a hot source never yields and its consumer starves in the worker's LIFO slot (same mechanism as the AppSink deadlock, gotcha 15). EOS and in-band events are never dropped or evicted (control pushes past a full leaky channel deliberately).
4. **`temporal::Timestamp` ≠ `clock::ClockTime`** — separate types, no conversion provided. Typed temporal joins use `Timestamp`; buffers/events use `ClockTime`.
5. **`typed::merge` is 2-source alternating interleave**, not N-way funnel. `typed::run_async` is `spawn_blocking` around the sync loop, not native async.
6. **`Executor::start` is sync**; only `run()` is async.
7. **Arena format is v5** (`ARENA_VERSION`): v4 added `slot_stride`/`alignment` (true stride read + validated by `from_fd`); v5 packed each `SlotHeader` into one `AtomicU64` and added the `orphaned` counter (#177). The v5 bump is about the *access pattern*, not layout (LE bytes are identical): a v4 peer CASing the state half-word alone would race a v5 sweep back into double allocation. Cross-process `new_avx` (32-byte) arenas are safe.
8. **The segment abstraction is gone** (2026-08 dead-surface sweep): `MemorySegment`, `IpcHandle`, `MappedFileSegment`, `HugePageSegment`, `AtomicBitmap`, `MemorySrc`/`MemorySink`/`SharedMemorySink`, and the `huge-pages`/`rdma` feature flags were deleted — nothing consumed them. `MemoryType` (caps vocabulary) and `DmaBufSegment` (live in the v4l2 path) survive.
9. **Vulkan Video (`vulkan-video`) decode is wired but hardware-unvalidated**: `VulkanH264Decoder` now really submits decode work — slice-header parsing via h264-reader, POC (types 0/1/2) + sliding-window/MMCO reference marking in `gpu/vulkan/h264_refs.rs` (pure logic, unit-tested), std SPS/PPS conversion in `h264_std.rs`, session/DPB/recorder built lazily from the stream's SPS (`new(Arc<VulkanContext>)` takes **no dimensions**), per-frame `vkCmdBeginVideoCodingKHR`→`vkCmdDecodeVideoKHR`→`vkCmdEndVideoCodingKHR` on the decode queue plus copy-out to staging on the graphics queue (images CONCURRENT-shared). Every failure path errors — no more GpuFrame over uninitialised memory. Scope v1: progressive 8-bit 4:2:0 Baseline/Main/High; scaling matrices ARE marshalled (h264_std returns owned `StdVideoH264ScalingLists` boxes kept alive across `new_h264`); a `frame_num` gap (lost reference) errors once then skips until the next IDR (`FrameNumGapDetector`, 7.4.3) instead of decoding corrupt; no interlaced, encode, or H.265/AV1. `HwDecoderElement` really bridges: pixels reach the pipeline via `HwVideoDecoder::read_frame` into arena slots with `set_video_dims` metadata, and **GPU memory is RAII** — `GpuBufferHandle` frees on Drop, `GpuMemory::free` no longer exists. `tests/vulkan_decode_tests.rs` decodes `tests/fixtures/tiny_64x64.h264` and green-skips without a capable device (ANV needs Gen12+; RADV is the validation target — #3 stays open for that). The empty `gpu` feature flag and the never-referenced `gpu-allocator` dependency have been removed.
10. **Every example file has an `[[example]]` entry in Cargo.toml**, feature-gated ones carrying `required-features`. Add one when you add an example: without it, cargo builds the file under default features and there is nowhere to hang the gate — which is how 42/43/44 ended up hand-rolling `#[cfg(not(feature))]` stub `main`s that printed a message instead of failing.
11. **All three benches are real** (`memory_pool`, `throughput`, `colorspace` — rewritten in 67f9e26): arena acquire/reclaim, `Buffer` clone cost (guards the no-syscall invariant), pool contention, `from_fd` attach; pipeline EOS throughput async+hybrid, fan-out per `LinkPolicy`, `AsyncRtBridge`/eventfd.
11b. **`elements::codec::hw_encoder`/`hw_decoder` need `vulkan-video` AND a codec feature** (the latter to compile `elements::codec` at all). No CI job sets both, so they had rotted un-compiled for a long time. Check them with `cargo check --features image-jpeg,vulkan-video`.
12. **`AlignmentStrategy::Interpolate` needs `B: Lerp`** — it resamples the *right* stream onto the left's timestamps, and only `TemporalJoin::try_emit_interpolated` honours it. Plain `try_emit` returns `None` for that variant (it used to silently run `Nearest(10ms)`, discarding the caller's `Duration`).
13. **`Error::PoolExhausted` is recoverable; every other `Err` from `process()` kills the element task.** The executor sheds that buffer (DropTracer + `parallax_buffers_dropped` + a rate-limited warn at the 1st/10th/100th consecutive) and continues, because a dropped frame beats a dead live pipeline. True for transforms AND sinks (#174 — the sink arm had no shed path before); sources answer `WouldBlock` instead, demuxers stall. `ExecutorConfig::shed_fatal_after` opts back into failing for batch work. Encoders must call `OutputArena::admit()` *before* encoding — shedding an encoded packet leaves a `frame_num` gap the decoder cannot recover from until the next IDR — while decoders must never skip an input and shed the output copy instead.
14. **`elements::codec` is compiled only when at least one codec feature is enabled** (see the `#[cfg(any(...))]` on `pub mod codec` in `elements/mod.rs`). Consequence: unit tests inside codec modules (including the always-present `EncoderElement`) do NOT run under default features — they run in CI's sensor combo and feature-specific jobs. When adding a codec feature, add it to that cfg list or the module silently won't compile.
14b. **`src/codec/annexb.rs` is ALWAYS compiled** — the Annex-B helpers (`nal_units`/`has_idr`/`extract_param_sets`/`annex_b_to_avcc`) need no codec feature, unlike `elements::codec` (Gotcha above). Don't feature-gate code that only uses them.
14c. **`ScaleEngine` (converters/) is the slice-level scaler; the `VideoScale` *element* wraps it** — one `ScaleMode` enum is shared by both, so a change to scaling behaviour touches both surfaces.
15. **`AppSink` is an `AsyncSink`** — register it with `add_async_sink`, not `add_sink` (#168). A full queue back-pressures by *awaiting* space; the old sync `Sink` waited on a condvar, which parked the tokio worker **and** stranded the puller its own notify had just woken into that worker's non-stealable LIFO slot — a deadlock `abort()` could not even break. Its await registers with `Notify::notified()` + `enable()` on purpose: `notify_one` (a pull freeing space) leaves a permit, `notify_waiters` (`set_flushing`/`clear`/FlushStart) does not, so a lazily-registered waiter misses a flush and hangs. Flushing **drops** the buffer and returns `Ok` — an `Err` from a sink is fatal to the task, so erroring would turn a seek into a teardown. **`IpcSink` is one too** (#172), and since #179 **`IpcSrc` is an `AsyncSource`** (`add_async_source` — its old sync `produce` blocked a worker inside a socket read once connected). The pair's per-buffer path is a shared-memory descriptor ring + ack ring with eventfd doorbells (`memory::IpcChannel`); the socket carries only RegisterChannel/RegisterArena/MetaOverflow/Shutdown, EOS rides the ring's state word, waits are doorbell awaits (5 s stall warn preserved), both directions are start-order independent, and the sink's ack reaping runs in a standing spawned task — never only in `consume` (deadlock: all arena slots pinned ⇒ source stuck ⇒ consume never called), and never by blocking in `Drop` (a blocked worker's LIFO slot strands the *peer's* task — the gotcha 15 mechanism). The rest of the roster followed (#172): `FileSink` (tokio::fs, flushed per buffer), `FdSink` (AsyncFd for pollable fds, direct writes for regular files), `UnixSink` (tokio net; the broken per-call-reconnect `AsyncUnixSrc`/`AsyncUnixSink` pair is deleted), `AutoVideoSink` (pacing wait is an await — a pause-frozen clock pends the future), `HttpSink` (spawn_blocking around ureq), `WebSocketSink` (tokio-tungstenite). No built-in sync `Sink` blocks its worker any more; `Mp4FileSink` and the test sinks stay sync (bounded page-cache writes).
16. **Data plane vs signaling plane** (#182, design.md principle 8): shared memory carries payloads, channels carry ~400 B `Buffer` handles — zero copies/allocs per hop. Don't propose replacing in-process links with a shm queue; the kanal experiment settled it (cancel-unsafe recv loses messages), and any replacement must meet the six invariants in design.md § 8.
17. Types that do NOT exist (stale docs may mention them): `CpuArena`, `HeapSegment`, `MemoryPool`, `SharedMemorySegment`, `PipelineExecutor`, `ElementSandbox`, `Affinity`, `VideoDecoder`/`DecoderElement` (video decoders impl `Element` directly, #160), `ControlSignal` (superseded by the flush epoch, #157), `PendingRecv` (the kanal-era stashed-future workaround), `LocalLink`/`LocalSender`/`LocalReceiver` (deleted with kanal — in-process links are the executor's per-edge `tokio::sync::mpsc` channels), `parallax-inspect`/`parallax-top` binaries (`parallax-launch` EXISTS since #187 — feature `cli`).
