# Codecs & Devices (feature-gated)

Guidance for elements under `src/elements/`. The always-loaded root `CLAUDE.md` holds the
cross-cutting invariants (Geometry-in-Metadata, `OutputArena`/`OutputBudget`, `PoolExhausted`
shedding, `Metadata::set_video_dims()` as the single geometry write); this file holds the per-codec and
per-device specifics.

| What | Types | Feature |
|------|-------|---------|
| H.264 | `H264Encoder`/`H264Decoder` (implement `Element` directly). `H264EncoderConfig::new()` takes **no dimensions**; geometry follows `Metadata` (a resize rebuilds the encoder + IDR). Live control via `control()`: a **bitrate change is seamless** (openh264-sys2 `SetOption(ENCODER_OPTION_BITRATE)`, no IDR); GOP/QP/rate-control/skip-frames rebuild (IDR). A no-op change does nothing. Counters via `stats()` → `EncoderStatsHandle`. **QoS consumer (#184)**: two consecutive `Event::Qos` underflows (proportion ≥ 1.5) enable rate-control frame skipping via its own control handle, a recovered report (< 1.1) restores — hysteresis because the toggle rebuilds (IDR); always returns `NotHandled` (observe-and-forward). **Defaults**: `rate_control = Bitrate`, `bitrate_bps = 2_000_000` (Bitrate + 0 is an error), `skip_frames = false`. In Bitrate mode with skipping off, `qp` is a quality *ceiling* (the band opens to 51). **`H264Decoder` carries the input AU's pts/dts/duration onto the decoded frame** — claimed smallest-PTS-first from a bounded in-flight queue, because openh264 emits in display order and a `decode()` call need not return the AU just fed — and its `Element::flush` drains the pictures openh264 still holds at EOS (the drain latch is per *cycle*, so a seek's discarded FlushStart drain doesn't eat the real EOS drain). **Seek resilience**: on `Event::FlushStart` the decoder REBUILDS its openh264 instance (mid-stream `flush_remaining` is an EOS operation that wedges openh264 into refusing everything until a later IDR) and clears pending metadata; a refused access unit (`dsRefLost` — post-seek open-GOP leading pictures, missing param sets) is *skipped with a rate-limited warn*, not fatal — same policy as the Vulkan decoder's frame_num-gap handling — erroring only after 300 consecutive refusals. Consequence: closed-GOP streams resume instantly after a seek; open-GOP streams (sync sample = SPS/PPS + non-IDR I-slice, e.g. some WEB-DL/YouTube MP4s) blank until the next true IDR because openh264 cannot start on a non-IDR slice and the wrapper's `DecoderConfig` exposes no error-concealment knob | `h264` |
| H.264 hardware | `V4l2M2mH264Encoder` (impl `VideoEncoder`, wrap in `EncoderElement`), `find_m2m_encoder(b"H264")` device probe; `V4l2CodedFormat::Fwht` is test-only (vicodec) | `v4l2-m2m` (build needs libclang + kernel headers) |
| **Hardware decode (VA-API)** | `VaapiDecoder::{h264,vp8,vp9}()` / `open(Codec)` — one element for any codec, `Element` directly. **Construction is a question, not an assertion**: it returns `Err` naming the reason (no DRM node, no driver, driver without this codec) and the caller falls back to software. Which codecs exist is a *packaging* decision as much as a hardware one — a patent-free build (Fedora's `libva-intel-media-driver`) omits H.264/HEVC on silicon that has the engines; `vainfo` is ground truth. **HEVC is not built at all** — `cros-codecs`' `h265` feature does not compile against its published release (#200), so `open(Codec::H265)` errors and, with no software HEVC decoder here either, HEVC does not play. The demuxers still read the track; the root CLAUDE.md gotcha 11d has the whole story. Emits packed NV12 with `set_video_dims`. Frames are pipeline-owned (`src/gpu/vaapi/frame.rs`): memfd → udmabuf → `DRM_PRIME_2`, **Y-tiled** — see the root CLAUDE.md gotcha, this is not negotiable and the readback de-tiles. Access units the decoder cannot take are **queued, never dropped** (bounded; a full queue is a real error, because `PoolExhausted` would make the executor *shed* the buffer and a skipped AU corrupts everything to the next keyframe). Factory names `vaapih264dec`/`vaapivp8dec`/`vaapivp9dec` — naming one explicitly means "I want the video engine", so construction failure is an error rather than a fallback. Measured on Comet Lake Gen9.5: **−77% player CPU** at 1080p H.264, −47% at 1440p VP9 | `vaapi` (needs libva-devel + libclang to build, a VA driver at runtime, and `/dev/udmabuf`) |
| AV1 | `Rav1eEncoder` (impl `Element` directly AND `VideoEncoder`; drains lookahead via `Element::flush`), `Dav1dDecoder` (impl `Element`; **External emission #194** — `output_media_caps` = `external_preferred`, and when the link negotiated `MemoryType::External` the dav1d `Picture` itself rides the pipeline in an `ExternalSlot` with real strides via `set_video_planes`, no de-stride copy; input side is zero-copy too, #195 — the owned input `Buffer` moves into `send_data` and dav1d releases it from its callback. Cpu-negotiated links keep the packed arena copy; a non-contiguous-planes picture falls back to it with a warn-once) | `av1-encode` / `av1-decode` |
| VP8/VP9 | `VpxDecoder::vp8()/vp9()/for_codec(VpxCodec)` (impl `Element` directly — the rule for all video decoders; VP8/VP9 have no reorder so input metadata maps 1:1). Build needs libvpx-devel + libclang (bindgen `generate` feature — the crate's bundled bindings stop at libvpx 1.13) | `vpx` |

| Containers | `TsMux`/`TsMuxElement`/`TsDemux`/`TsDemuxElement` [`mpeg-ts`] — **`TsDemuxElement` is seekable in TIME by translation** (#163 phase B): it estimates a byte offset from `TsByteIndex` (PCR anchors harvested during `push`, linear interpolation, packet-grid snapped, clamped to the total the source's byte `Segment` carries) and answers the seek with `EventResult::forward(seek.derive(Bytes, …))`; under two anchors it refuses rather than guessing. With `SeekFlags::ACCURATE` it iterates (#173): the first post-flush PTS is judged against the target, and a >500 ms miss stages a `derive_refined` correction through `Demuxer::take_upstream_event` (≤3 rounds, SeekDone held until done). `flush()` calls `reset_parser()` — `reset()` minus stats and index, because the index is what makes the *next* seek work. Sync detection confirms a candidate 0x47 against the following packets. A stream with head-only PSI (`TsMuxConfig::psi_interval == 0`, the default) is unseekable: the parser reset never recovers. **Seek stop + trick play (#165)**: both source-style demuxers honor `seek.stop` (playback really ends there; the executor turns that Eos into `SegmentDone` for a SEGMENT-flagged seek, else real EOS); rate>1 = keyframe-only fast-forward (both); **rate<0 = keyframe-only reverse, BOTH containers** (#165): MP4 walks sync samples exactly (backward `seek_all_to_time(cursor, Before)` from the range top), MKV walks its cue table backward (`produce_reverse` repositions at the last cue ≤ cursor and scans that cluster for the cue's video keyframe — one keyframe per cue point, coarser than stss when a muxer cues sparsely; **cue-less files refuse reverse**, no backward index exists); video only, true decreasing PTS — the reverse segment maps them to increasing running time; both need a stop or a known duration, else the seek is refused. `Mp4Mux`/`Mp4FileSink`/`Mp4Demux`/`Mp4DemuxSource` [`mp4-demux`], `MkvDemux` [`mkv-demux`] — MkvDemux is itself the source-style `Demuxer` (Matroska interleaves frames in cluster order, no per-track cursors); H.264 **and HEVC** CodecPrivate (avcC/hvcC) → Annex-B with the parameter sets in band on keyframes — one branch, since both codecs are length-prefixed NALs with out-of-band parameter sets and differ only in the record that carries them (`annexb::{NalConfig, parse_avcc, parse_hvcc}`, shared with `Mp4Demux`); VP8/VP9/AV1/audio pass through; `MkvAudioInfo::codec_private` is raw (real ASC for AAC, OpusHead, Xiph-laced Vorbis triple); dts==pts (Matroska has no DTS); header-stripping compression restored, zlib/encryption refuse to route; **seek (#158): parallax owns the cue index** — `mkv_cues.rs` scans SeekHead→Cues on the raw reader *before* `MatroskaFile::open` (matroska-demuxer 0.8 mis-resolves ffmpeg's CueRelativePosition against the first cluster; our table uses CueClusterPosition only), and a `SharedReader` keeps a second handle so a seek does `file.seek(0)` (parser-state reset) + raw reposition at the cue's Cluster start; **per-track skip** (`Vec<(track, ticks)>` — audio can't clear video's skip) then `video_resync` (evaluated only after the video skip clears, so mid-GOP leaks are structurally impossible), with `with_scan_budget` (default 256) bounding discards per produce() via empty-`Routed` yields; cue-less files fall back to the crate's linear seek, then rewind+skip; PoolExhausted-safe via a `pending` stash (executor retries produce()). In-pipeline demuxing (#76): `add_demuxer` + `link_pads(demux, "video"/"audio", ..)`; `Mp4DemuxSource` is source-style (owns the reader, no input link), `TsDemuxElement` is fed bytes. `Mp4Demux` converts H.264 **and HEVC** samples to Annex-B with the parameter sets in band on keyframes (`annexb::avcc_to_annex_b`); the `hvcC` record is recovered by the raw `stsd` scan under both sample-entry names (`hvc1`, `hev1`) because the mp4 crate exposes neither. VP9 passes through length-prefixed. AAC: `Mp4AudioInfo` carries the esds fields (`object_type`/`freq_index`/`channel_config`) plus a synthesized 2-byte `audio_specific_config` (exact for object types 1–30, standard freq indices; `None` for escape encodings — the mp4 crate parses the descriptor lossily); `.with_adts_aac(true)` prepends ADTS per sample. Time seek: `seek_to_time(track, ns, SeekSnap)` (stts+stss keyframe snap, direction per `SeekSnap::{Before,After,Nearest}`), `seek_all_to_time(ns, SeekSnap)` (video-anchored multi-track; secondary tracks always land at-or-before the reference) | |

**The codec-surface rule (#160)**: *video decoders implement `Element` directly* (h264/dav1d/vpx — 1:1 metadata carry, own arena, decode straight into the slot; the old `VideoDecoder` trait + `DecoderElement` wrapper are deleted: a wrapper cannot carry input PTS/metadata through); *audio codecs implement `AudioDecoder`/`AudioEncoder` and wrap in `AudioDecoderElement`/`AudioEncoderElement`* (the wrapper stamps `AudioRaw` metadata and owns the recycle hook); *video encoders implement `VideoEncoder` and wrap in `EncoderElement`* (rav1e also impls `Element` for its lookahead drain). **ACCURATE clipping (#165)**: all three video decoders (h264/dav1d/vpx) track the Time segment through `handle_downstream_event` and decode-but-drop output frames below `segment.start` (`SegmentClip` in `codec/common.rs`, forward rate only); their flush drains loop past clipped frames instead of ending the EOS drain early. **Encoder input is borrowed (#146) and may be strided (#196)**: `VideoEncoder::encode(VideoFrameRef<'_>)` / `AudioEncoder::encode(AudioSamplesRef<'_>)` — `Copy` views built straight over the input buffer's bytes (no per-encode copy). `VideoFrameRef` carries the frame's `PlaneLayout`, not three `stride_*` fields (those could not express a plane's *offset*, so planes had to be dense and in order): read planes with `plane(i) -> Option<FramePlane>` / `y_plane()`, and rows with `FramePlane::row(y)`. An encoder that does so overrides `VideoEncoder::accepts_strided_input() -> true` (openh264, rav1e, v4l2-m2m do); `EncoderElement` advertises `MemoryCaps::external_or_cpu()` on its input only for those, so a packed-only encoder is never offered a codec-owned frame. the owned `VideoFrame`/`AudioSamples` remain the decoder-output types (dav1d's queue, `AudioDecoder`'s return + `recycle` currency) and convert with `.as_view()`. The plane/sample accessors live on the views (returning the data's lifetime) and the owned types delegate. `VideoEncoder` has `force_keyframe()` plus defaulted `set_bitrate`/`set_keyframe_interval`/`set_qp` that `Err` when the codec cannot comply — rav1e/opus/aac do not override them. `EncoderElement::new(enc)` takes no format: it reads `Metadata.format` per buffer, maps caps pixel formats to codec ones with per-format strides (I420/I422/I444/NV12/10-bit), errors on RGB/packed input (needs `VideoConvert` upstream) and on a buffer that declares no format at all, and re-sizes its arena on a geometry change. Its `input_media_caps()` pins the encodable pixel-format list with `Any` geometry, so negotiation still auto-inserts a `VideoConvert`.

Muxer sync: `MuxerSyncState`/`MuxerSyncConfig::new().with_mode(SyncMode::{Auto|Strict|Loose|Timed}).with_interval_ms(..)`, `PadInfo::new(name, StreamType).required()/.optional()`; `TsMuxConfig::new().add_track(TsMuxTrack::new(pid, TsMuxStreamType::H264).video())`.
