# Codecs & Devices (feature-gated)

Guidance for elements under `src/elements/`. The always-loaded root `CLAUDE.md` holds the
cross-cutting invariants (Geometry-in-Metadata, `OutputArena`/`OutputBudget`, `PoolExhausted`
shedding, `Metadata::set_video_dims()` as the single geometry write); this file holds the per-codec and
per-device specifics.

| What | Types | Feature |
|------|-------|---------|
| H.264 | `H264Encoder`/`H264Decoder` (implement `Element` directly). `H264EncoderConfig::new()` takes **no dimensions**; geometry follows `Metadata` (a resize rebuilds the encoder + IDR). Live control via `control()`: a **bitrate change is seamless** (openh264-sys2 `SetOption(ENCODER_OPTION_BITRATE)`, no IDR); GOP/QP/rate-control/skip-frames rebuild (IDR). A no-op change does nothing. Counters via `stats()` → `EncoderStatsHandle`. **Defaults**: `rate_control = Bitrate`, `bitrate_bps = 2_000_000` (Bitrate + 0 is an error), `skip_frames = false`. In Bitrate mode with skipping off, `qp` is a quality *ceiling* (the band opens to 51). **`H264Decoder` carries the input AU's pts/dts/duration onto the decoded frame** — claimed smallest-PTS-first from a bounded in-flight queue, because openh264 emits in display order and a `decode()` call need not return the AU just fed — and its `Element::flush` drains the pictures openh264 still holds at EOS | `h264` |

| Containers | `TsMux`/`TsMuxElement`/`TsDemux`/`TsDemuxElement` [`mpeg-ts`] — **`TsDemuxElement` is seekable in TIME by translation** (#163 phase B): it estimates a byte offset from `TsByteIndex` (PCR anchors harvested during `push`, linear interpolation, packet-grid snapped, clamped to the total the source's byte `Segment` carries) and answers the seek with `EventResult::forward(seek.derive(Bytes, …))`; under two anchors it refuses rather than guessing. With `SeekFlags::ACCURATE` it iterates (#173): the first post-flush PTS is judged against the target, and a >500 ms miss stages a `derive_refined` correction through `Demuxer::take_upstream_event` (≤3 rounds, SeekDone held until done). `flush()` calls `reset_parser()` — `reset()` minus stats and index, because the index is what makes the *next* seek work. Sync detection confirms a candidate 0x47 against the following packets. A stream with head-only PSI (`TsMuxConfig::psi_interval == 0`, the default) is unseekable: the parser reset never recovers. `Mp4Mux`/`Mp4FileSink`/`Mp4Demux`/`Mp4DemuxSource` [`mp4-demux`], `MkvDemux` [`mkv-demux`] — MkvDemux is itself the source-style `Demuxer` (Matroska interleaves frames in cluster order, no per-track cursors); H.264 CodecPrivate avcC → Annex-B with in-band SPS/PPS on keyframes; VP8/VP9/AV1/audio pass through; `MkvAudioInfo::codec_private` is raw (real ASC for AAC, OpusHead, Xiph-laced Vorbis triple); dts==pts (Matroska has no DTS); header-stripping compression restored, zlib/encryption refuse to route; **seek (#158): parallax owns the cue index** — `mkv_cues.rs` scans SeekHead→Cues on the raw reader *before* `MatroskaFile::open` (matroska-demuxer 0.8 mis-resolves ffmpeg's CueRelativePosition against the first cluster; our table uses CueClusterPosition only), and a `SharedReader` keeps a second handle so a seek does `file.seek(0)` (parser-state reset) + raw reposition at the cue's Cluster start; **per-track skip** (`Vec<(track, ticks)>` — audio can't clear video's skip) then `video_resync` (evaluated only after the video skip clears, so mid-GOP leaks are structurally impossible), with `with_scan_budget` (default 256) bounding discards per produce() via empty-`Routed` yields; cue-less files fall back to the crate's linear seek, then rewind+skip; PoolExhausted-safe via a `pending` stash (executor retries produce()). In-pipeline demuxing (#76): `add_demuxer` + `link_pads(demux, "video"/"audio", ..)`; `Mp4DemuxSource` is source-style (owns the reader, no input link), `TsDemuxElement` is fed bytes. `Mp4Demux` converts H.264 samples to Annex-B with in-band SPS/PPS on keyframes (`annexb::avcc_to_annex_b`); H.265/VP9 pass through length-prefixed. AAC: `Mp4AudioInfo` carries the esds fields (`object_type`/`freq_index`/`channel_config`) plus a synthesized 2-byte `audio_specific_config` (exact for object types 1–30, standard freq indices; `None` for escape encodings — the mp4 crate parses the descriptor lossily); `.with_adts_aac(true)` prepends ADTS per sample. Time seek: `seek_to_time(track, ns, SeekSnap)` (stts+stss keyframe snap, direction per `SeekSnap::{Before,After,Nearest}`), `seek_all_to_time(ns, SeekSnap)` (video-anchored multi-track; secondary tracks always land at-or-before the reference) | |

**The codec-surface rule (#160)**: *video decoders implement `Element` directly* (h264/dav1d/vpx — 1:1 metadata carry, own arena, decode straight into the slot; the old `VideoDecoder` trait + `DecoderElement` wrapper are deleted: a wrapper cannot carry input PTS/metadata through); *audio codecs implement `AudioDecoder`/`AudioEncoder` and wrap in `AudioDecoderElement`/`AudioEncoderElement`* (the wrapper stamps `AudioRaw` metadata and owns the recycle hook); *video encoders implement `VideoEncoder` and wrap in `EncoderElement`* (rav1e also impls `Element` for its lookahead drain). `VideoEncoder` has `force_keyframe()` plus defaulted `set_bitrate`/`set_keyframe_interval`/`set_qp` that `Err` when the codec cannot comply — rav1e/opus/aac do not override them. `EncoderElement::new(enc)` takes no format: it reads `Metadata.format` per buffer, maps caps pixel formats to codec ones with per-format strides (I420/I422/I444/NV12/10-bit), errors on RGB/packed input (needs `VideoConvert` upstream) and on a buffer that declares no format at all, and re-sizes its arena on a geometry change. Its `input_media_caps()` pins the encodable pixel-format list with `Any` geometry, so negotiation still auto-inserts a `VideoConvert`.

Muxer sync: `MuxerSyncState`/`MuxerSyncConfig::new().with_mode(SyncMode::{Auto|Strict|Loose|Timed}).with_interval_ms(..)`, `PadInfo::new(name, StreamType).required()/.optional()`; `TsMuxConfig::new().add_track(TsMuxTrack::new(pid, TsMuxStreamType::H264).video())`.
